# /daily — リリース準備の日次ループ

docs/TODO.md（リリース準備バックログの正本）から次のタスクを **1つだけ** 消化する。
「実行 → 観測 → 修正」のループを毎回完結させ、develop を常に green に保つ。

## 手順

### 1. 前提チェック
- `git status` が clean かつ現在ブランチが develop であること。
- 汚れている・別ブランチの場合は**何もせず停止**し、状態を報告して人間の判断を仰ぐ。

### 2. タスク選択
- `docs/TODO.md` を P0 → P1 → P2 の順に走査し、最初の `- [ ]`（未着手）を選ぶ。
  - `⛔` 行が付いているタスクはスキップ（ブロック中＝人間の判断待ち）。
  - `- [~]`（着手中）が残っていればそれを最優先で再開する。
- 選んだタスクに「検証:」が無ければ着手せず、TODO.md にその旨を追記して**次のタスク**へ。
- 未完タスクが1つも無ければ「全タスク完了」を報告して終了。

### 3. サイズ判定・分割
次のいずれかに該当する見込みなら、タスクを `TXXXa / TXXXb / …` のサブタスクに分割して
TODO.md を書き換え（各サブタスクにも「検証:」必須）、**先頭サブタスクのみ**今回実施する:
- 変更ファイルが5つを超えそう
- 独立した成果物が複数ある
- 検証がその場で完結しない（実機・外部アカウント等が必要）

### 4. 種別分岐
- **code**（既定）: 下記 5〜6 へ。
- **marketing**: アプリコードには触らない。成果物は `docs/marketing/` に Markdown で作成
  （Web 検索可）。検証＝タスクの「検証:」に書かれた受け入れ条件のセルフチェック。
- **docs**: ドキュメントのみ変更。JSON 等を触った場合は `npm run lint`。

### 5. 実装（ガードレール）
- `vendor/` `dist/` `node_modules/` は変更禁止（vendor は読むのも禁止）。
- 依存パッケージの追加は原則禁止（無料・オフライン方針）。必要と判断したら⛔ブロック扱いにして人間に相談。
- preload API は追加のみ（既存の変更・削除禁止）。
- CLAUDE.md の規約に従う。

### 6. 検証（必須・スキップ禁止）
- タスクの「検証:」に書かれた手順を実行する。
- コード変更時は最低 `npm run test:fast`。FFmpeg・書き出し・main プロセスを触ったら `npm test`。
- 検証で新しい回帰を見つけたら、このタスクの一部として直すか、TODO に新タスクとして追記する。

### 7. 記録とコミット
- TODO.md の該当行を `- [x]` にし、進捗ログへ1行追記:
  `- YYYY-MM-DD: TXXX 完了。<要約>（<検証結果>）`
- 実装と TODO.md 更新を **1コミット**にまとめる。メッセージは日本語で
  `TXXX <一行要約>` 形式。**push はしない**（人間の指示があった時のみ）。

### 8. 失敗時（develop を green に保つ）
検証が通らない・実装が詰まった場合:
1. コミットせず `git stash push -u -m "daily-blocked-YYYYMMDD-TXXX"` で退避。
2. TODO.md の該当タスクに `⛔ ブロック: <理由>（stash: daily-blocked-YYYYMMDD-TXXX）` を追記。
3. TODO.md **のみ**をコミットして停止・報告。

### 9. 報告（1起動1タスク厳守）
タスクが完了しても次のタスクには進まない。最後に以下を1〜3行で報告:
- 今日やったこと（タスクID・要約・検証結果）
- 次のタスク候補（TODO.md の次の `- [ ]`）
- 気づいたこと（あれば。TODO への追加提案など）
